# git-drs line-count audit

## Baseline

The tracked tree contains 30,731 physical Go lines. Syntax-aware counts split those into 15,631 production code lines and 11,486 test code lines. Tests therefore account for 42.4% of Go code. There are no generated Go files.

At the baseline snapshot, the worktree also contained one untracked 177-line test file. The tracked figures above exclude it; the implementation comparison below includes it in the starting total.

The largest production areas by physical line count are:

`cmd` and `internal` together contain 17,325 of 17,829 production physical lines. The size is primarily CLI breadth plus Git/LFS, transfer, provider, authentication, and compatibility policy.

## Accepted cleanup

The immediate safe cleanup is 554 production physical lines. It consists of dormant transfer deletion logic, unreachable upload probing, selectors and LFS APIs retained only by tests, obsolete push discovery, dead copy-record wrappers, and several tiny forwarding or no-op helpers. Removing those paths also permits deletion of at least 528 test lines, plus the tests for the obsolete push path.

Discovery separately identified `cmd/bucket.addServerBucketScope` as a direct `Buckets().AddScope` substitution. The `upsertServerBucket` substitution was initially held pending proof that Syfon preserved its credential-only payload. Focused transport tests later validated and enabled both changes; see the implementation result below.

Local consolidation can remove roughly another 160 lines from duplicated glob matching, bucket matching, atomic JSON writing, and destructive-command display helpers. Those changes require contract tests and are not included in the 554-line safe subtotal.

`internal/drslog` also contains about 120 lines of stale call-by-call comment narration. Removing that text improves readability but does not reduce executable code.

## Implementation result

The cleanup reduced production Go from 17,829 to 16,912 physical lines and from 15,631 to 14,942 code lines. Across production and tests, Go fell from 30,908 to 29,936 physical lines. Tests account for 13,024 of the remaining physical Go lines.

`internal/transfer` production code fell from 2,958 to 2,600 physical lines (2,349 code lines). It now delegates the reusable transport boundary to Syfon: upload and download engines, multipart transfer, retries and checkpoints, hash normalization, low-level progress context, scoped authorization metadata, and DRS access resolution. The remaining transfer code owns Git-specific inventory and cache semantics, cross-scope record reuse, access-method and Globus policy, expiring access-URL refresh, metadata batching, and CLI progress. Syfon v0.3.8 has no equivalent high-level APIs for those contracts.

The bucket commands now also use Syfon's `Buckets().AddScope` and `Buckets().Put` operations. Other reductions came from deleting dormant destructive reconciliation, obsolete push discovery, test-only production APIs, duplicate shell helpers, and consolidating path matching, bucket selection, confirmation, and atomic JSON writing.

Verification after integration:

- `go test ./... -count=1`: 420 tests passed in 48 packages.
- `go vet ./...`: no findings.
- `deadcode ./...`: only public library entry points and test-helper roots remain; no additional private production candidate was found.
- `git diff --check`: clean.

The six generated coverage artifacts were removed from version control, deleting 96,190 generated lines and 5,897,714 bytes. Two duplicated monorepo shell implementations were replaced with thin wrappers that preserve their default-resource behavior and delegate to the canonical utilities.

## Non-source bulk

Six tracked generated coverage outputs contain 96,190 lines and 5,897,714 bytes. They are already ignored and regenerated by repository tooling, so they should be removed from version control.

The repository also tracks 9,334 Markdown lines, 6,019 shell-script lines, and about 5.4 MB of binary documentation assets. Binary newline counts are not source LOC. The shell bulk is mainly end-to-end and integration harnesses, not product implementation.

## Keep decisions

The remaining transfer, lookup, remote runtime, resolver, Globus, Git integration, filter, DRS object, cache, public client, and inventory code has live callers or explicit external and persisted compatibility contracts. Syfon owns transport primitives, but git-drs still owns Git reachability, pointer/cache state, command behavior, scope policy, retries, registration decisions, and progress integration.

Normal push remains non-destructive. The dormant DRS/storage deletion reconciler is part of the accepted cleanup because storage audits belong to Gecko/Syfon.
