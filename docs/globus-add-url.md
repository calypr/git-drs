# Adding Globus Objects with `git drs add-url`

`git drs add-url` creates Git pointers and local DRS metadata for files that
already exist in a Globus collection. It does not stage or download source
files during import.

## CLI behavior

The `globus://` scheme selects the Globus path automatically. `--recursive` is
deprecated and no longer needed.

Add one file:

```bash
git drs add-url \
  globus://<collection-id>/project/sample.bam \
  data/sample.bam
```

Add a directory tree:

```bash
git drs add-url \
  globus://<collection-id>/project/release/ \
  data/release
```

Select files with a quoted wildcard:

```bash
git drs add-url \
  'globus://<collection-id>/project/release/**/*.bam' \
  data/bam --dry-run

git drs add-url \
  'globus://<collection-id>/project/release/**/*.bam' \
  data/bam
```

Quote wildcard URLs so the shell does not expand them. Supported patterns are:

- `*` for zero or more characters within one path component;
- `?` for one character within one path component;
- `[...]` for a character class; and
- `**` for zero or more complete path components.

A directory or wildcard import requires an explicit destination directory. A
single file may omit its destination, in which case its collection path is used
as the repository path.

## Discovery and identity

For a single path, `add-url` asks Globus for file status. If the path is a
directory, it switches to recursive listing. A trailing slash skips the status
request and lists the directory directly. Wildcards are applied to a recursive
listing rooted at the path before the first wildcard.

Globus listings provide path, size, and `last_modified`, but not a content
SHA-256. When no checksum is supplied, `git-drs` derives a deterministic local
OID from:

- the member's complete `globus://` URL;
- its size; and
- its Globus `last_modified` value.

The pointer marks this value with the Git LFS extension
`ext-0-gitdrsplaceholder`. The value is a source-version identity and cache key,
not a content checksum. Local DRS metadata therefore leaves `checksums` empty.
During hydration, git-drs checks the declared size and relies on Globus transfer
verification; it does not compare downloaded bytes with the placeholder.

If Globus omits `last_modified`, checksum-less import stops instead of creating
an identity that cannot detect a same-size replacement.

## Optional authoritative manifest

`--manifest` remains available when authoritative SHA-256 values already
exist. It is optional and is not generated by git-drs.

```text
path\tsize\tsha256
reads/a.fastq\t1234\t<64-character SHA-256>
reads/b.fastq\t5678\t<64-character SHA-256>
```

For a directory or wildcard selection, the manifest must describe exactly the
selected files and sizes. Manifest SHA-256 values become content checksums and
are verified after hydration.

## Materialized repository state

For every selected member, `add-url` writes:

- one pointer at the corresponding destination path;
- one local DRS object retaining the exact member `globus://` URL; and
- one pre-commit cache entry.

Directory and wildcard imports also add one read-only
`destination/**` rule to `.gitattributes`. Existing files, symlink traversal,
empty wildcard results, and conflicting read-write tracking rules are rejected.
Use `--dry-run` to inspect the resolved source URL, destination, and size without
writing repository state.

Registration still happens on `git drs push`. Hydration later uses the stored
member URLs; it does not re-list the collection or re-evaluate the original
wildcard. Push and pull resolve the selected OIDs together with Syfon's bulk
checksum endpoint instead of issuing one lookup per pointer.

## Design decisions

The retired `tests/globus-user-integration-test/cmd/tutorial-manifest` helper
copied the tutorial collection locally only to calculate SHA-256 values. That
made test setup perform a second transfer and made recursive import appear to
require checksums even though single-file `add-url` already supported missing
ones.

The Globus implementation now shares the same missing-checksum model as other
provider URLs. Discovery stays provider-specific, while pointer creation,
local DRS metadata, registration, and pull continue through the existing
git-drs paths. Client-side wildcard matching keeps committed objects explicit:
the selected member URLs are frozen at import time, and later collection
changes require a new import and Git commit.

The placeholder extension is intentionally explicit. A bare SHA-256-shaped
placeholder is indistinguishable from a real content hash to pointer readers,
which can cause false checksum failures or promote the placeholder into content
metadata. The marker preserves compatibility with the Git LFS pointer grammar
while allowing git-drs to apply size-only validation to checksum-less objects.
